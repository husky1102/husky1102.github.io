# 博客嵌入模式实施提示词

以下正文可以直接复制给在博客仓库中工作的开发助手。

---

请在 `/home/husky/blog/digital-garden` 中实现适合内嵌阅读的博客界面。先阅读该仓库的 `AGENTS.md`，检查当前代码、线上页面和工作区状态，再实施、验证并提交博客侧修改。不要修改个人主页仓库；最后给出个人主页需要接入的具体步骤。不要把尚未完成的跨站联调报告为已完成。

## 背景与已完成的个人主页改动

- 个人主页：`https://husky1102.github.io/`，博客容器页：`https://husky1102.github.io/blog_embed/`。
- 博客原站：`https://www.husky1102.top/`，文章继续由 Obsidian / Digital Garden 插件发布。
- 个人主页博客页已将完整主导航收成约 48px 的返回栏，只有“返回主页”、独立打开、外层主题按钮；已移除底部横线、重复博客标题栏和外层菜单。
- 返回栏沿用线上侧栏配色：浅色背景 `#f0f2ec`、深色背景 `#1e2321`。不要只根据这些记录硬编码，先确认博客实际生效的配色变量。
- 原生 iframe 的 `id` 是 `blog-frame`，当前 `src` 仍是 `https://www.husky1102.top/`，尚未添加 `embed=1`，也没有实现 `postMessage` 接收、主题同步或握手隐藏返回栏。
- 外层占满视口，iframe 填充返回栏下方空间，只有博客内部滚动。主站其他页面仍使用原来的完整导航。

## 最终视觉目标

让访客感受到一个完整的博客阅读空间。保留内嵌方式，主站地址仍为 `/blog_embed/`；博客原网址也能独立访问。

1. **桌面布局**：在最终联调完成、外层返回栏隐藏后，左侧目录从视口顶部开始，右侧直接展示正文。统一站点名称、搜索、文章目录、返回主页与阅读设置的位置。不要再增加横跨正文的重复导航或大标题栏。
2. **分隔方式**：嵌入模式中取消或显著弱化侧栏右侧的边框、内阴影，依靠轻微背景色差、留白和对齐建立层次。排查父级或伪元素，避免仅去掉 border 后仍残留竖线。不要以粗边框、发光、厚阴影、额外卡片包裹整个页面。
3. **手机布局**：只保留一条紧凑的博客工具栏，容纳返回主页、目录、搜索和主题。目录打开时作为抽屉出现，支持遮罩关闭、Escape、焦点管理及焦点返回，正文不横向溢出。
4. **主题**：使用博客现有的深浅色变量。最终只保留博客内部一个主题入口，并同步个人主页外层；不能出现外层浅色、内层深色。保留减少动态偏好，避免两个窗口各播一次主题动画。
5. **品牌和阅读**：通过站点配置或模板将通用的 `unTitled` 替换成合适的统一名称，例如“Husky 的博客”。搜索、目录、文章大纲和字号功能应当可用，但关系图不应持续挤占正文，可按需展开。角色保留收起入口，避免遮挡正文和手机操作区域。

## 嵌入模式与兼容性

- 明确实现 `?embed=1`，通过根节点类或属性限定嵌入样式，避免全局覆盖破坏独立博客。
- 独立访问不带参数的原网址应维持完整、可用的站点界面。
- 在嵌入模式中，目录链接、双链、搜索结果、最近更新、上一页/下一页等站内导航应保留嵌入状态；浏览器前进后退、文章刷新、深链接与锚点也要可用。不要给外部链接附加嵌入参数。
- iframe 内“返回主页”应明确打开 `https://husky1102.github.io/` 的顶层窗口，不能把个人主页再次装进 iframe。独立打开应在新标签页打开当前文章，并去掉嵌入专用参数。
- 父页面还没有接入协议时，博客应正常阅读，不等待握手才显示正文，也不能因未收到消息导致错误或空白。

## 建议采用的对接协议（需要新实现，当前两边尚未具备）

消息均为对象，带 `version: 1`；`theme` 仅允许 `light` 或 `dark`：

```js
// 个人主页 → 博客：初始化；博客收到后设置主题并重新发送 ready，防止首次消息错过。
{ type: 'husky:embed:init', version: 1, theme: 'dark' }

// 博客 → 个人主页：仅在嵌入布局、返回主页入口和主题控制确实可用后发送。
{ type: 'husky:embed:ready', version: 1, theme: 'dark',
  capabilities: { returnHome: true, themeControl: true } }

// 双向：应用对方主题时不要再次回发，避免消息循环。
{ type: 'husky:embed:theme', version: 1, theme: 'light' }
```

- 博客端必须校验 `event.origin === 'https://husky1102.github.io'` 和 `event.source === window.parent`，限定嵌入上下文，验证版本、类型和字段；发送消息指定精确 `targetOrigin`，不要使用 `*`。
- 首次加载可先使用博客正常主题，收到合法初始化消息后以主站传入主题为准。之后用户通过博客按钮切换时通知主站。握手只报告实际能力，不声称父端已经同步或移除了返回栏。
- 将消息处理接入已有主题函数，不再创建另一套相互竞争的主题状态或动画。
- 本地联调用受控测试页面或代理模拟真实父站来源；不要为了开发方便放开生产来源校验。

## 内容边界

不要直接改写 `src/site/notes/` 中的笔记正文、frontmatter、双链或插件生成的资源路径。首页的 README 文案和重复文章清单属于后续内容整理事项：可以提出建议，但如果必须改笔记源内容，应先请求确认，优先由用户在 Obsidian 中修改后同步。本次优先改模板、站点配置、样式、脚本、必要测试和文档。

## 验证与交付

- 分别检查原站独立模式、`?embed=1` 直接访问、可信父站 iframe、未接入协议的父页以及不可信消息来源。
- 检查 320 / 390 / 768 / 1440px，深浅两种模式，键盘、触摸、减少动态偏好、存储不可用、快速主题切换。
- 实际打开首页和至少一篇文章，验证搜索、目录、双链、前进后退、刷新、返回主页、独立打开、目录抽屉及其焦点行为。
- 用测试父页验证握手重发和双向主题消息。测试父页通过不等于真实个人主页已完成联调，须明确区分。
- 提供桌面和手机的深浅色截图，运行仓库规定的构建与适当测试，按仓库要求提交。
- 最后输出个人主页的后续接入清单：先安装带来源和 iframe 窗口校验的消息监听器，再给 iframe 加 `embed=1`；在加载时发送初始化消息；仅收到合法 ready 且所需能力齐全后隐藏 `.blog-layout .masthead`，让 iframe 占满视口；加载新文档时恢复返回栏作为后备，重新握手；根据主题消息同步外层背景、浏览器主题色与状态，取消外层重复主题入口。加载失败或未握手时保留返回和独立打开能力。

不要用裁切 iframe、负边距、遮盖线条或跨域 DOM 注入来模拟整合。
